Ukay Finds: turning a Facebook resale page into a searchable storefront

How a scrolling wall of Facebook posts became a fast, filterable product catalog — built solo, from problem definition to production, using vanilla JavaScript and GitHub Pages.

Role: Sole Developer Stack: JavaScript, Vite, GitHub Pages Timeline: Design → Launch
View Live Site ↗

The Problem

The client resells secondhand ("ukay-ukay") clothing and accessories, and like most small resale operations, ran the entire business through Facebook. Every new item meant a new post: a photo, a caption with size and price, and then fielding the same questions over and over in the comments — "Is this still available?", "What size is this?", "Can I reserve it?"

As inventory grew, the page became unusable as a catalog. There was no way to search by size or collection, no way to see what was still in stock without scrolling through months of posts, and no way for shoppers to save items they liked for later. Every sale depended on the seller personally answering direct messages.

The Approach

Rather than build a full e-commerce platform with checkout and payments — overkill for a resale business that finalizes sales over Messenger — the goal was a lightweight, fast-loading browsing layer that plugs into the seller's existing workflow instead of replacing it.

That meant three product decisions up front:

  • Browsing, not buying. The catalog's job is to help shoppers find and reserve items, not process payment — that stays on Messenger, where the seller already operates.
  • Zero backend cost. Hosting on GitHub Pages meant no server bills and no infrastructure to maintain for a small side business.
  • Fast on a phone. Most of the seller's customers browse and shop from mobile, often on inconsistent data connections, so the site needed to stay light.

What Was Built

Before

  • Inventory scattered across individual Facebook posts
  • No filtering by size, collection, or availability
  • Buyers had to scroll and DM to check stock
  • No way to save or shortlist items

After

  • Searchable catalog with collection and size filters
  • Live availability status per item
  • Favorites list so shoppers can build a shortlist
  • One-tap reserve that hands off to Messenger

The interface is a single-page catalog built in JavaScript with Vite handling the build and dev tooling — fast hot reload during development and a lean, optimized bundle for production, without the overhead of a full framework for a project this size. Items are organized by collection and size, with client-side filtering so browsing feels instant. When a shopper finds something they want, "reserve" opens a pre-filled Messenger conversation, keeping the final step exactly where the seller already does business.

Outcome

The seller now manages a single source of truth for inventory instead of an ever-growing feed of posts, and shoppers can self-serve the browsing experience that used to require a direct message.

What I'd Improve Next

Being candid about the roadmap: the next iteration would move availability status into a small structured data file (or lightweight CMS) so the seller can update stock without touching code, and add basic analytics to see which collections get the most interest. Both are scoped but not yet built.
